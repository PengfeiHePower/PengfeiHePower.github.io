TRAJECT-Bench

A trajectory-aware benchmark that checks how LLM agents select, parameterize, and order tool calls.

Code 🤗 Dataset Paper
TL;DR — Getting the final answer right is not enough. TRAJECT-Bench checks how an LLM agent uses tools: whether it picks the right tools, fills in the right arguments, and calls them in the right order.
1,228executable tools
5,670queries
3–10+tools per trajectory
2difficulty levels

Why trajectories?

Agents increasingly rely on tools to finish real-world tasks, yet most benchmarks only grade the final answer. An agent can land on the right answer with a broken process, or fail because of one wrong argument early in a long chain. TRAJECT-Bench makes the tool-use trajectory itself the object of evaluation.

What’s inside

🧰

Production-style tools

Over 1,000 high-fidelity, executable APIs across practical domains such as travel, finance, and music.

🔀

Breadth and depth

Parallel calls test breadth; interdependent sequential chains test depth.

🎯

Simple vs. hard queries

Every trajectory comes with an explicit query and an implicit one where the agent must infer the needed tools.

📏

Trajectory-level metrics

Exact match, tool inclusion, argument correctness, dependency and order satisfaction, plus final accuracy.

Key findings

1

Scaling tool use is a universal challenge. Performance drops for every model as trajectories get longer, and the sharpest drop is the step from short to mid-length trajectories.

2

Implicit queries are hard. When the user does not name the steps, models struggle to infer which tools are needed, which causes cascading errors in selection and arguments.

3

Recurring failure modes. Models confuse similar tools and select tools without checking whether their parameters fit the request.

4

Retrieval is not a silver bullet. Retrieval-based tool selection helps little on simple queries and becomes a severe bottleneck on hard ones, while agentic methods such as ReAct with dynamic retrieval are more robust.
